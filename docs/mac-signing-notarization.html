Update: as of v1.1.1, releases are signed with a stable self-signed identity ("ScratchPad Local Dev" — see docs/mac-release.md), not ad-hoc. That already fixes the repeated Screen Recording prompt: TCC grants now survive reinstalls and auto-updates. Why a real Developer ID still helps. The self-signed cert fixes TCC persistence but isn't trusted by Apple, so Gatekeeper still blocks a fresh install until xattr -cr strips the quarantine flag. A real Developer ID Application certificate has a stable identity too, but — unlike a self-signed one — Apple trusts it, so once notarized there's no Gatekeeper warning at all, on any Mac, with no manual Terminal step.

The flow

One-time setup you do this

  1. Enroll in the Apple Developer Program

    $99/year, requires an Apple ID with two-factor authentication enabled.

    developer.apple.com/programs →

  2. Create a Developer ID Application certificate

    Either path works:

    • Xcode → Settings → Accounts → your Apple ID → Manage Certificates → + → "Developer ID Application"
    • Or via developer.apple.com/account/resources/certificates → — download the .cer, double-click to install into Keychain Access (login keychain)

    Verify it's usable for signing:

    security find-identity -v -p codesigning | grep "Developer ID Application"

    Note the identity string it prints, e.g. Developer ID Application: Your Name (TEAMID1234).

  3. Create an app-specific password for notarization

    Simplest option — go to appleid.apple.com/account/manage →, Sign-In and Security → App-Specific Passwords → generate one (label it e.g. "scratchpad-notarize").

    You'll also need your Team ID, from developer.apple.com/account → Membership details.

    Alternative: an App Store Connect API key — more setup, no password to rotate. Only worth it if the app-specific password becomes a hassle.

Build changes once you have credentials

Tauri's macOS bundler signs and notarizes automatically when these env vars are set — no tauri.conf.json changes needed:

export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID1234)"
export APPLE_ID="your-apple-id@example.com"
export APPLE_PASSWORD="app-specific-password-from-above"
export APPLE_TEAM_ID="TEAMID1234"

npm run tauri:build
This replaces ad-hoc signing entirely. install-local.sh's manual re-sign step (the "ScratchPad Local Dev" cert workaround) becomes unnecessary for anything built this way — the Developer ID identity is already stable. Keep install-local.sh as-is for quick unsigned local dev builds where you don't want to wait for notarization.

Update docs/mac-release.md's build step once this is in place — the env vars above go right before npm run tauri:build; the rest of the release checklist (DMG + .app.tar.gz + updater signature) stays the same.

Verifying it worked

codesign -dv --verbose=4 /Applications/ScratchPad.app

Should show your Developer ID identity, not adhoc.

spctl -a -vv /Applications/ScratchPad.app

Should say accepted, source=Notarized Developer ID.
